# Illustrative FrontDesk use cases

> **Fictional examples — not customer reviews or testimonials.** The profiles,
> companies, circumstances and outcomes below are invented to explain possible
> workflows. They do not claim that anyone purchased, used or endorsed FrontDesk.

1. **US Shopify operations lead — fictional.** Wants order questions from web
   chat and email in one queue. FrontDesk can answer approved FAQs and route an
   account-specific request to a teammate.
2. **UK independent retailer support manager — fictional.** Needs British date,
   currency and spelling conventions. FrontDesk can apply the UK region setting
   while keeping a human handoff available.
3. **US bilingual customer-care manager — fictional.** Serves English- and
   Spanish-speaking website visitors. The web widget can present either language.
4. **UK SaaS customer-success lead — fictional.** Wants Slack notifications and
   a shared inbox for unresolved onboarding questions.
5. **US ecommerce agency owner — fictional.** Manages separate client deployments.
   Tenant-scoped knowledge and connectors help prevent cross-client data mixing.
6. **UK IT service desk lead — fictional.** Needs internal notes, assignment and
   takeover when an automated answer is insufficient.
7. **US knowledge manager — fictional.** Uploads PDF, DOCX, PPTX and XLSX material
   and reviews cited answers before expanding the approved knowledge set.
8. **UK accessibility coordinator — fictional.** Evaluates keyboard operation,
   focus visibility and screen-reader announcements with the published test plan.
9. **US customer-experience analyst — fictional.** Uses CSAT and queue metrics to
   identify gaps in approved support content.
10. **UK privacy operations lead — fictional.** Uses tenant-scoped export and
    approved deletion workflows while retaining audit evidence.
11. **US help-desk supervisor — fictional.** Lets public FAQs remain guest-accessible
    while requiring step-up identity before account-specific tools are exposed.
12. **UK managed-service provider — fictional.** Runs the application in its own
    environment and keeps model and connector credentials under purchaser control.
13. **US social support lead — fictional.** Routes purchaser-owned Meta and
    WhatsApp conversations into the same operational queue as web chat.
14. **UK support engineer — fictional.** Uses the diagnostic command before a
    shift and follows the recovery runbook after an outage simulation.
15. **US support director — fictional.** Starts with Ollama locally, measures
    latency and answer quality on company-specific cases, then decides whether a
    cloud model is appropriate.

These examples describe supported workflow patterns, not guaranteed results.
Actual performance depends on deployment, source material, model, integrations,
staffing and configuration.
